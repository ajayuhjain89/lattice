# Lattice — Threat Model

Status: Foundation draft (Phase 0), revisited at the end of every phase that touches
authz, retrieval, answering, tracing or ingestion. **Phase 10 review (2026-10-02):** the
whole model was re-read against the code with identity and provisioning added; T3, T15,
T16 and T19 revised, T22–T25 added; findings and the isolation review at the end.
Related: `trust-boundaries.md`, `security-model.md`, `authorization-model.md`.

Assets, in priority order: (1) document content and metadata users aren't authorized
for; (2) other organizations' anything; (3) question/answer history (can itself be
sensitive: "Is Acme about to churn?"); (4) credentials and session tokens; (5)
integrity of answers (users act on them).

Adversaries considered: curious or malicious employee (authenticated, low privilege);
a user of another tenant; a compromised or misconfigured organization identity provider
(Phase 10); an author of content that gets ingested (customer writing a
ticket, anyone posting in Slack); a compromised or careless model provider; an
operator with log access; a bug in our own code (the most likely adversary).

## Phase 10 review findings (2026-10-02)

- **Audit atomicity (ADR-014 residual) — fixed.** A second access writer (SCIM) made
  the code-only guarantee too weak: deferred constraint triggers now refuse to commit an
  unaudited access write by the API role (migration 0013).
- **Cross-tenant identity — designed out.** Global users and `external_identities` would
  have let one organization's provider attach to or alter another's person; provisioned
  people are organization-owned users and identities are scoped to the connection.
- **Script injection defence — strengthened.** The web app's `script-src 'unsafe-inline'`
  was replaced by a per-request nonce with `'strict-dynamic'` (verified in Playwright:
  every script carries the nonce, no violations, a fresh nonce per load).
- **Third-party logging — tightened.** httpx logged every outbound URL at INFO; now
  WARNING (T12).
- **Accessibility defect found on the way** (not a security issue): the request
  reference on tinted error callouts failed contrast; fixed.
- **Dependencies.** `pip-audit` (locked set with hashes) and `pnpm audit`: no known
  vulnerabilities on 2026-10-02; now a CI job (`make audit`).
- **Isolation review (pen-test style).** Every served route is classified and swept
  (`tests/security/test_route_inventory.py`): anonymous → 401, member → one 403 from
  every administrator route, SCIM without its token → 401, and another organization's
  real identifiers (evidence, trace, source, member, document, grant, SCIM resource)
  answer exactly like random ones and change nothing. No finding.
- **Unchanged and re-confirmed:** authorization inside retrieval (policy `authz-2`
  untouched), D-8 to D-19, the operational-metadata rules (§10 of the security model).

## Rejected optimizations (would weaken guarantees)

- Retrieving top-K without the predicate and filtering in Python ("faster ANN").
- Embedding per role / per permission set (breaks immediate revocation, multiplies storage).
- Caching answers across users with "similar permissions".
- Letting the model choose which documents to fetch via tools in the Ask path.
- Returning 403 on unreadable evidence IDs (leaks existence).
